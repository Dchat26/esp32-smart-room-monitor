## 1. `'BTN_PIN' was not declared in this scope` 컴파일 에러

**문제**
- 컴파일 시 `'BTN_PIN' was not declared in this scope`, `'digitalwrite' was not declared in this scope` 에러 발생

**원인**
- 문장 끝 세미콜론(`;`) 누락
- 함수 이름 대소문자 오류 (`digitalwrite` → 올바른 이름은 `digitalWrite`)
- C++은 대소문자를 구분하며, 세미콜론 하나가 빠지면 뒤쪽에서 엉뚱한 에러가 연쇄적으로 발생할 수 있다

**해결**
- 세미콜론 추가, 함수 이름 철자 수정
- 코드를 고친 뒤에도 에러 표시가 남아 있었는데, Wokwi는 **다시 실행(컴파일)해야 에러 표시가 갱신**됨

**배운 점**
- 에러가 여러 개면 **첫 번째 에러부터** 고친다
- `was not declared in this scope` → 철자 오류나 선언 누락을 먼저 의심한다

## 2. 버튼을 누르지 않아도 LED가 켜져 있음

**문제**
- 실습 A에서 버튼을 누르지 않았는데도 LED가 계속 켜져 있음

**원인**
- 푸시버튼 다리 4개 중 **같은 번호의 핀(2.l, 2.r)**에 GPIO19와 GND를 연결함
- 같은 번호 핀은 **버튼 내부에서 항상 연결**되어 있어, GPIO19가 늘 GND에 붙어 있는 상태
- 항상 `LOW` → `pressed`가 항상 `true` → LED 계속 켜짐

```
  1.l ──── 1.r    ← 내부에서 항상 연결
     [버튼]          (누르면 위아래가 이어짐)
  2.l ──── 2.r    ← 내부에서 항상 연결
```

**해결**
- GPIO19는 **2.l**, GND는 **1.r**처럼 **서로 다른 번호의 핀**에 연결
- 누를 때만 1번과 2번이 이어져 정상 동작

**배운 점**
- 부품의 내부 연결 구조를 먼저 확인해야 한다 (Wokwi에서는 핀에 마우스를 올리면 이름 확인 가능)
- 코드가 맞는데 동작이 이상하면 **배선을 먼저 의심**한다

## 3. 한 번 눌렀는데 여러 번 인식됨 (바운싱)

**문제**
- 실습 B(토글)에서 버튼을 한 번 눌렀는데 시리얼에 `press #`가 2~3개씩 찍힘
- 토글이 짝수 번 일어나 LED가 반응하지 않는 것처럼 보임

**원인**
- 기계식 버튼은 눌리는 순간 금속 접점이 수 ms 동안 **붙었다 떨어졌다를 반복**한다 (바운싱)
- ESP32는 매우 빠르게 `loop()`를 반복하므로 이 흔들림을 여러 번의 누름으로 인식

**해결**
- `millis()` 기반 디바운싱 적용: 값이 바뀔 때마다 시각을 기록하고, **50ms 동안 값이 유지될 때만** 진짜 입력으로 인정

```cpp
if (reading != lastReading) {
  lastChangeTime = millis();          // 흔들리면 타이머 리셋
}
if (millis() - lastChangeTime > DEBOUNCE_MS && reading != stableState) {
  stableState = reading;              // 안정된 변화만 확정
  if (stableState == LOW) { /* 토글 */ }
}
lastReading = reading;
```

- 결과: 한 번 누를 때마다 `press #`가 정확히 1씩 증가

**배운 점**
- 하드웨어 입력은 이상적인 0/1이 아니라 노이즈와 흔들림이 있다
- `delay()`로 기다리면 다른 작업이 멈추므로, `millis()`로 경과 시간만 확인하는 논블로킹 방식을 쓴다
- 디바운싱 시간(50ms)은 반응 속도와 안정성 사이의 트레이드오프다
